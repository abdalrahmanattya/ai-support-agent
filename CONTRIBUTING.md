# Contributing

Open an issue before a substantial change so its behavior and AWS cost can be bounded. Keep the fictional customer dataset free of real personal data and preserve the boundary that deterministic services own authorization and business state.

Run `./scripts/build.sh` and `./scripts/check.sh` before proposing a change. Live AWS checks must use a temporary environment, sanitized results, and the documented teardown audit. Never commit credentials, deployment identifiers, local session files, or raw customer memory.
